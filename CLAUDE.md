# Black Highlighter

iOS/iPadOS/Mac Catalyst/visionOS app for redacting text in images. UIKit app, Swift 6, generated with Tuist, dependency injection with Factory.

## Project generation

- The Xcode project and workspace are generated by Tuist and not checked in. Tool versions are pinned in `mise.toml`.
  - `mise run generate`: regenerate after adding or removing files, targets, or dependencies.
  - `mise run spm-install`: resolve the SPM packages in `Tuist/Package.swift`.
  - `mise run module <Name>`: scaffold a new Capabilities module (sources, tests, and the target file).
- Make target changes in `Tuist/ProjectDescriptionHelpers/Targets/{Capabilities,Legacy,Products}/<Name>.swift` and register them in `Project.swift`. Don't edit the `.xcodeproj`.
- Build settings that every module shares live in `Tuist/ProjectDescriptionHelpers/TargetExtensions.swift` (`capabilitiesTarget`, `capabilitiesTestTarget`, `capabilitiesDoublesTarget`). Use these helpers rather than declaring targets by hand.
- Localized strings and asset catalogs in a module's `Resources/` are turned into the `Strings.…` and `<Module>Asset.…` accessors (templates in `Tuist/ResourceSynthesizers`). Add new strings to `Resources/en.lproj/Localizable.strings` and regenerate.

## Module layout

- `App`, `Action`, `Photo`, `Widgets`: product targets (the app and its extensions).
- `Modules/Capabilities/<Name>/`: feature modules. New code goes here, never in Legacy.
  - `Sources/`, `Tests/`, optional `Resources/`, and optional `Doubles/`. Doubles become a separate `<Name>Doubles` framework for other modules' tests to use.
- `Modules/Legacy/`: older modules (`Core`, `Editing`) still being broken up into Capabilities. Move code out of them, not in.
- `Modules/TestHelpers/`: shared test utilities. `TestHelpersInterface` holds the protocols that doubles depend on.

## Swift and concurrency

- Every target is Swift 6 (`SWIFT_VERSION` in `Tuist/ProjectDescriptionHelpers/Shared.swift`), with approachable concurrency and `ExistentialAny` turned on. Don't add per-target language-mode opt-outs. Always write `any Protocol` for existentials.
- Don't add unmanaged, unstructured `Task { }` or `Task.detached { }` calls. Instead:
  - hop to the main actor explicitly: `MainActor.assumeIsolated` when the callback is guaranteed to arrive on main, otherwise `DispatchQueue.main.async`;
  - or store the `Task` handle and cancel it;
  - or use structured concurrency (`async let`, task groups, `async` functions).
  The existing sites are tracked in #469.
- UIKit only. SwiftUI is allowed only in `Widgets/`, and a custom SwiftLint rule enforces this (see #436).

## Dependency injection (Factory)

- Each module declares its dependencies in `Sources/Dependencies.swift` as a `Container` extension, and dependencies are typed as protocols:
  ```swift
  public extension Container {
      var renderer: Factory<any PhotoRenderer> {
          Factory(self) { DataPhotoRenderer() }
      }
  }
  ```
- Consumers use `@Injected(\.renderer) private var renderer`. Don't add initializer parameters with defaults, or static accessors, as a way to inject dependencies; recent work is converting those to Factory.
- Add `FactoryKit` as an `.external` dependency on the target in its Tuist target file.

## Tests

- Write new tests with Swift Testing (`import Testing`, `@Test`, `#expect`, `#require`), not XCTest.
- If a suite registers Factory overrides, mark it `@Suite(.container)` (from `FactoryTesting`) and override with `Container.shared.<dep>.register { … }`.
- Test doubles go in the module's `Doubles/` folder, named by kind: `Stub…` for canned return values, `Spy…` for recording calls.
- `Highlighter.xctestplan` controls which test targets run. A new test target needs to be in both `Project.swift` and the test plan, or it won't run.
- Run tests with the **Highlighter** scheme, because the test plan sets the `IS_TEST` environment variable. Other schemes give false failures. `scripts/test.ps1` shows the full `xcodebuild` invocation.

## Style

- Lint with `mise run lint` (SwiftLint, configured in `.swiftlint.yml`). Trailing commas are required in multi-line collection literals.
- Every file starts with the header:
  ```swift
  //  Created by <Author> on <M/D/YY>.
  //  Copyright © <YYYY> Cocoatype, LLC. All rights reserved.
  ```
- Group imports into blocks separated by blank lines, alphabetized within each block: Apple frameworks, then third-party (`FactoryKit`, `FactoryTesting`), then first-party modules, then `@testable` imports.

## Git and GitHub

- The default branch is the current `release/*` branch (e.g. `release/26.2`), not `main`, and PRs target it. The git remote is named `github`.
- Branches are named `issue/<number>`. Create them tracking the local release branch (`git checkout -b issue/<n> --track release/<version>`), and push with `git push github <branch>`, without `-u`, so the upstream stays the release branch.
- Commit messages are short imperative summaries ("Factory PhotoRenderer", "Fix default zoom to safe areas").
- The repo is public, but it isn't open to outside contributions (see README).
